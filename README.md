# KEREGE

KEREGE — B2B-платформа оптовых закупок для Кыргызстана. Первый пилот: Бишкек.

## MVP v0.1
- Регистрация и вход через Supabase Auth (email + пароль).
- Две роли: покупатель и поставщик.
- Каталог активных оптовых товаров.
- Заявки покупателей поставщикам.
- Совместные закупки с атомарным учётом объёма через PostgreSQL RPC.
- Row Level Security (RLS) для ограничения доступа.

## Структура
- `index.html` — адаптивный web-клиент, который также можно установить как PWA на Android.
- `supabase/migrations/202611160001_init.sql` — схема PostgreSQL, триггеры, RPC и RLS.
- `docs/SETUP.md` — инструкция по запуску.

## Быстрый запуск
1. Создайте проект в Supabase.
2. Выполните SQL-миграцию из `supabase/migrations/202611160001_init.sql` в SQL Editor.
3. В Authentication включите Email provider.
4. Разместите `index.html` на GitHub Pages или другом HTTPS-хостинге.
5. В форме приложения введите Supabase Project URL и publishable key.
6. Создайте два тестовых аккаунта: поставщика и покупателя.

## Безопасность
- В браузере допустим только Supabase publishable key (или legacy anon key) при корректно включённом RLS.
- Никогда не добавляйте `service_role`, secret key, пароль БД или токены в клиентский код, GitHub или чат.
- Телефон в MVP — контактное поле, а не подтверждённый номер.
- Платежи не подключены. Заказы и участие в совместных закупках на этом этапе являются заявками/намерениями, а не оплатой или гарантированным бронированием товара.

## Ограничения MVP
Нет SMS-авторизации, чата, push-уведомлений, онлайн-оплаты, модерации документов и административной панели. Перед публичным запуском нужны тесты RLS, проверка поставщиков, юридические документы, правила возврата и обработка споров.
